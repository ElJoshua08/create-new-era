Live reloading

With dev_hotswap=true (the default), most changes reach a running game without a restart.

How it works#

runClient starts on the JetBrains Runtime with -XX:+AllowEnhancedClassRedefinition, which accepts almost any class change (new methods, fields, classes), and a debug port on 127.0.0.1:5005. When the game starts, the build records which classes it started with. Then:

Terminal
./gradlew hotswap                 # recompile, push changed classes into the running client
./gradlew hotswap -Pport=5006     # same for runServer, which listens on 5006

Only classes that changed since the game started are sent. The swap is done by tools/hotswap/HotSwap.java over JDWP.

What needs what#

You changedTo see it
Java code: logic, rendering, the editor, the Lua API./gradlew hotswap
Textures, models, lang./gradlew hotswap copies them too; then press F3+T in game
Recipes, tags, loot tables and other data/reload in game
Registration: new blocks, items, block entities, network payloadsRestart the game

Code that already ran keeps its old effects: a class swapped in changes what runs next, not what's already registered or stored. If something looks stale, restart.

Turning it off#

Set dev_hotswap=false in gradle.properties to launch dev runs on the default JDK, without the debug port.
