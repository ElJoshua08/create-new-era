Building from source

There's no release yet, so building the jar yourself is the way to try the mod. You only need a JDK 17 or newer to start Gradle; it downloads JDK 21 on its own.

Build and run

git clone https://github.com/ElJoshua08/create-new-era.git
cd create-new-era

./gradlew build              # jar ends up in build/libs/
./gradlew runClient          # play with the mod
./gradlew runGameTestServer  # in-game tests: blocks, recipes, screens joining, Lua programs, Ponder structures
./gradlew runData            # regenerate blockstates, item models, loot tables, tags, en_us

On Windows use gradlew.bat instead of ./gradlew.

Dev environment

runClient downloads a realistic modpack into run/ the first time, so the mod is tested against what players actually run. Every file is pinned from Modrinth and checksum-verified (SHA-1); a mismatch stops the build.

  • Sodium, Lithium, ModernFix, FerriteCore, ImmediatelyFast, Entity Culling
  • Iris with Complementary Reimagined (enabled on first launch) and Unbound
  • Create: Aeronautics and Sable

The mods go into the run folders like a real install, not onto the classpath, so client-only mods never reach the dev server. The server and GameTest runs use run/server/ and only get Aeronautics and Sable. The shaderpack is picked once; after that, your in-game choice wins.

Switching groups off

Each group has a flag in gradle.properties:

# Sodium + optimization mods in runClient
dev_client_mods=true
# Iris + Complementary shaderpacks in runClient
dev_shaders=true
# Create: Aeronautics + Sable in every run
dev_aeronautics=true

To bump a version, replace its URL and SHA-1 in gradle/dev-mods.gradle. The downloads run as the setupDevClient and setupDevServer tasks before the matching run tasks.

Asset tools

Block textures and models are generated by script so they stay consistent with Create's palette. They're plain Python 3 with Pillow; the renderer also uses NumPy.

ScriptWhat it does
tools/textures/gen_textures.pyDetail atlases, with palettes sampled from Create's casings. Block bodies reuse Create's own casing textures by reference; the atlas only holds the parts Create doesn't have: screens, dials, LEDs, ports. Also draws the Control Plate item.
tools/models/gen_models.pyBlock models from compact element lists. Output is plain vanilla JSON, so Blockbench opens it directly.
tools/render/iso_render.pyRenders block models to PNG without launching the game. Made the block images on this site.
tools/screen/proto_screen.pyPrototype of the flip-pixel screen look, used to pick the screen resolution before writing the in-game renderer.
tools/ponder/gen_ponder.pyWrites the structures the Ponder scenes play out on. The scenes themselves live in NewEraPonderScenes.java; positions must match.
 
python3 tools/textures/gen_textures.py
python3 tools/models/gen_models.py

# each --assets folder contains assets/<namespace>/{models,textures}
python3 tools/render/iso_render.py out.png create_new_era:block/brass_computer \
    --assets src/main/resources --assets <create assets> --assets <vanilla assets> \
    --size 384 --yaw 270     # yaw 270 shows the computer's front

python3 tools/screen/proto_screen.py OUT_DIR Monocraft.ttf --res 32 48 64 --blocks 3 2
python3 tools/ponder/gen_ponder.py

The renderer needs Create's and Minecraft's assets to draw the casings; point --assets at an extracted copy of each jar. Join model names with + to draw several models into one tile.
