Los programas funcionan sobre [Cobalt](https://github.com/cc-tweaked/Cobalt), la máquina virtual de Lua 5.2 de CC: Tweaked. Esta página lista todo lo que tiene a mano un programa. Las sugerencias del editor muestran la misma lista con una línea sobre cada cosa.

## Globales

| Función | Qué hace |
| --- | --- |
| `print(...)` | Escribe sus argumentos en la consola en una línea, separados por tabuladores. Las tablas muestran lo que tienen, como `{speed = 64, stress = {capacity = 2048, used = 512}}`, hasta unos pocos niveles; las funciones salen como `<function>`. |
| `sleep(seconds)` | Espera ese tiempo en tiempo de juego, redondeado hacia arriba a ticks enteros. `sleep()` y `sleep(0)` esperan un tick. Cualquier cosa que no sea un número da error. |
| `require(name)` | Ejecuta una vez otro archivo de este ordenador y devuelve lo que devolvió. Mira [Archivos y require](./files.mdx). |

## os

Solo estas tres. No hay `os.time`, `os.date` ni acceso a archivos.

| Función | Qué hace |
| --- | --- |
| `os.clock()` | Segundos de tiempo de juego desde que arrancó el programa. |
| `os.sleep(seconds)` | Igual que `sleep`. |
| `os.speed()` | La velocidad del ordenador en RPM, negativa cuando el eje gira al revés. A 0 el programa está en pausa, así que casi nunca ve un 0. |

## redstone

También está como `rs`. Cada función recibe primero un lado: `"front"`, `"back"`, `"left"`, `"right"`, `"top"` o `"bottom"`, contados desde el frente del ordenador. Cualquier otro nombre para el programa con un error como `unknown side 'north'`.

| Función | Devuelve | Qué hace |
| --- | --- | --- |
| `getInput(side)` | booleano | Si entra alguna señal por ese lado. |
| `getAnalogInput(side)` | de 0 a 15 | La fuerza de la señal que entra. |
| `setOutput(side, on)` | | Envía una señal completa (15) por ese lado, o la apaga. `on` tiene que ser un booleano. |
| `setAnalogOutput(side, strength)` | | Envía una señal de 0 a 15. Otros números dan error. |
| `getOutput(side)` | booleano | Si este ordenador envía algo por ese lado. |
| `getAnalogOutput(side)` | de 0 a 15 | La fuerza que envía este ordenador por ese lado. |
| `getSides()` | tabla | Los seis nombres de lado: front, back, left, right, top, bottom. |

Más en [Redstone](./redstone.mdx).

## bus

Los dispositivos de la red de datos de este ordenador. Cómo montar una está en [El bus de datos](./bus.mdx).

| Función | Devuelve | Qué hace |
| --- | --- | --- |
| `bus.list()` | tabla | Todos los dispositivos a los que llega el ordenador, del más cercano al más lejano. Cada entrada es una tabla con `name`, `type`, `distance`, `readable` y `writable`. |
| `bus.get(name)` | dispositivo | Un dispositivo por su nombre. Da el error `no device named '…' on this computer's network` si no se llega a él. |

Los campos de una entrada de `bus.list()`:

| Campo | Ejemplo | Significado |
| --- | --- | --- |
| `name` | `"creative_motor"` | Lo que le pasas a `bus.get`. |
| `type` | `"create:creative_motor"` | El id del bloque. |
| `distance` | `2.8` | Distancia en línea recta desde el ordenador, en bloques, con un decimal. No es la longitud del cable. |
| `readable` | `true` | Tiene un puerto de salida en la red, así que puedes leerlo. |
| `writable` | `false` | Tiene un puerto de entrada en la red, así que puedes darle órdenes. |

## Dispositivos

`bus.get` devuelve una tabla con `name`, `type` y una función para cada cosa que sabe hacer ese tipo de bloque. Puedes llamarlas con punto o con dos puntos; `motor.getSpeed()` y `motor:getSpeed()` funcionan igual.

Para leer hace falta un puerto de **salida** en el dispositivo, y para darle órdenes uno de **entrada**. Un puerto de datos de latón y la conexión propia de un control de panel hacen las dos cosas. Si llamas a una función que los puertos no permiten, el programa se para con un mensaje que dice qué puerto falta, por ejemplo `creative_motor.setSpeed needs an input port on creative_motor`. Los errores de las funciones de dispositivos, como un argumento que no vale, señalan la línea de tu programa que hizo la llamada.

Lo que sabe hacer cada tipo de bloque está en [Dispositivos](./devices.mdx). Las sugerencias del editor muestran la misma lista para el dispositivo que guarda una variable, con una línea sobre cada función.

### read y onChange

Todo dispositivo con funciones tiene también `read()`: todo lo que se puede leer de él en un solo valor. En una máquina es una tabla con lo que le toque de esto: `speed`, `overstressed`, `stress`, `targetSpeed`, `items`, `fluids` y `state` (su estado de bloque). En un control de panel es el valor del propio control: el `true` o `false` de un pulsador, el número de un mando.

| Función | Qué hace |
| --- | --- |
| `device.onChange(fn)` | Ejecuta `fn(value, device)` cada vez que cambia algo del dispositivo, hasta que el programa termine. `value` es lo que da `read()`. |

Algunos dispositivos tienen ayudas hechas sobre `onChange`:

| Ayuda | En | Ejecuta |
| --- | --- | --- |
| `onPress(fn)` | un pulsador de panel | `fn(device)` cada vez que se pulsa |
| `onKey(fn)` | un teclado de panel | `fn(key, device)` por cada tecla, de `"0"` a `"9"`, `"*"` o `"#"` |
| `onKeyDown(fn)`, `onKeyUp(fn)` | una Linked Typewriter | `fn(key, device)` cuando cada tecla baja o sube |
| `onKey(fn)` | una Linked Typewriter | `fn(key, down, device)` para las dos |
| `onMessage(fn)` | un chat log | `fn(message, device)` por cada mensaje, `{player, text, time}` |
| `onClick(id, fn)` | una pantalla de latón | `fn(player, device)` cuando se pulsa el botón con ese id |
| `onTouch(fn)` | una pantalla de latón | `fn(x, y, player, device)` por cada toque, en sus puntos |

Mira [Reaccionar a los cambios](./devices.mdx#reaccionar-a-los-cambios).

## Librerías estándar

Están `string`, `table`, `math`, `coroutine`, `utf8` y `bit32`, con sus funciones de siempre. También las funciones básicas: `pairs`, `ipairs`, `next`, `select`, `type`, `tostring`, `tonumber`, `error`, `assert`, `pcall`, `xpcall`, `setmetatable`, `getmetatable`, `rawget`, `rawset`, `rawequal`, `rawlen` y `load`.

Las cadenas tienen sus métodos: `("hola"):upper()`.

## Errores

Un error para el programa y la consola lo muestra en rojo, empezando por el archivo y la línea: `startup.lua:4: attempt to call a nil value`. Pincha en él para ir ahí. Usa `pcall` para los errores que te esperas:

```lua
local ok, err = pcall(function()
  return bus.get("chest").count("minecraft:coal")
end)
if not ok then
  print("no se llega al cofre: " .. err)
end
```
