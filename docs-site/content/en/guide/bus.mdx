The data bus is how a computer reaches the machines around it. You stick **data ports** on the blocks you want to use, join them to the computer with **cable**, and the program can read and control those blocks by name.

A port doesn't change the block it sits on. A chest with a port is still a chest, and a press with a port still presses. You don't need the Universal Adapter for any of this; in this version it does nothing yet.

## Data ports

<Recipe id="bus_port" />

Right-click any face of any block with a data port: it sticks where you clicked, as a small mini-block on that face. Several ports fit on one face. Hit a port to knock it off and get it back; the block underneath stays.

On a block smaller than a full cube, like a slab, a sensor or a Create machine with a thin side, the port sits on the block's real surface where you clicked, not floating at the edge of the block's space.

A copper data port faces one of two ways:

- **Output**, amber light. Programs can **read** the block: speed, stress, items, fluids, its state. A new port starts as an output.
- **Input**, green light. Programs can **give it orders**: set a motor's speed, open a door, power it with redstone.

Right-click a port with Create's wrench to switch it between output and input. Sneak and wrench it to take it off.

## Brass data ports

A **Brass Data Port** is read and given orders through the same port. There's no mode to pick, and the wrench doesn't switch it; sneak and wrench it, or hit it, to take it off. It's the port to use when a block needs both, like a Creative Motor you want to read and set.

## One cable per port

Each port takes **one** cable. A second one is refused with *That port already has its cable: bring several together at a Port Hub*. So a device is the end of a line: to join several devices, run their cables to a **port hub** or a **splice**.

## Port hubs

The **Port Hub** is a brass block with four sockets on every face, 24 in all, joined to each other inside it. Run each device's cable into a socket and they're all on one network.

Each socket takes one cable. The hub keeps colours apart the same way a splice does: a red cable and a blue cable in the same hub don't join, and bare copper joins any (see [Cables](./cables.mdx#colours)). The sockets come with the hub; you can't knock them off, and the hub isn't a device, so it doesn't show up in `bus.list()`.

## The computer's own ports

Every Brass Computer comes with four ports, two on each side in a brass panel. They're always there, can't be knocked off, and turn with the computer. Each takes one cable like any other port.

A computer can't get more ports of its own. Port Expansions are gone: they have no recipe and aren't in the creative tab, though ones already on a computer still work. To reach more devices, run a cable from the computer to a port hub and gather them there.

## Splices

<Recipe id="cable_splice" />

A cable splice joins cables in the middle of a run. It sticks to a face like a port, but it isn't a device: nothing shows up in `bus.list()` for it. Unlike a port, a splice takes as many cables as you like. Use one to branch a cable, or to pin a long run to a wall halfway.

## Panel controls

Panel controls (buttons, lamps, knobs, gauges, flight instruments and the rest) have a connection built into their plate. Click anywhere on the control with a spool and the cable goes into it; there's no port to add. A control is read and given orders through that one connection, and it takes one cable. See [Screens & panels](./screens-panels.mdx).

## How a network is put together

A network is everything you can reach by following cables from the computer's ports, through splices and port hubs. Each block on it with a port is one **device**. What the program can do with it depends on its ports:

| Ports on the network | The program can |
| --- | --- |
| a copper port set to output | read it |
| a copper port set to input | give it orders |
| one of each | both |
| a brass port, or a panel control's own connection | both |

The computer doesn't list itself. Two computers on the same network see each other as devices.

## Device names

A device's name is its block id without the namespace: a chest is `chest`, a Creative Motor is `creative_motor`, Aeronautics' Throttle Lever is `throttle_lever`. When the name is taken, it gets a number: `chest_2`, `chest_3`. The name is given the first time a computer sees the block and stays with that block until it's broken, even when Aeronautics makes it part of a ship. There's no way to rename devices in game yet.

The quickest way to see the names is to ask:

```lua
for _, d in ipairs(bus.list()) do
  print(d.name, d.type, d.distance, d.readable, d.writable)
end
```

`bus.list()` gives the devices nearest first. Or type `bus.get("` in the editor: the suggestions list every device, nearest first. Picking one outlines that block in the world for ten seconds after you close the editor.

Breaking a block removes its ports and drops them as items. It leaves the network, and its name is freed.
